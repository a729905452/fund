# 数据字段契约（M0 实证核定版）

核定日期：2026-09-24 ｜ 标的样本：sz000636（风华高科）｜ 数据来源：腾讯财经公开接口
核定方法：原始响应实证 + 跨接口交叉验证，不推测。原始样本存于 `samples/m0_raw_*`。

## 一、接口清单

| 用途 | 端点 | 编码 | 认证 |
|------|------|------|------|
| 实时行情 | `https://qt.gtimg.cn/q={symbol}` | GBK | 无 |
| 日线K线 | `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param={symbol},day,,,{count},qfq` | UTF-8 JSON | 无 |
| 分钟K线 | `https://ifzq.gtimg.cn/appstock/app/kline/mkline?param={symbol},m{1|5},,{count}` | UTF-8 JSON | 无 |

symbol 格式：市场前缀小写 + 代码，如 `sz000636` / `sh600519`。

## 二、实时行情字段（`~` 分隔，共 88 字段）

已核定字段：

### ⚠️ field[30] 专项结论（四次休市采样实证）

| 请求时间 | field[30] 值 |
|----------|--------------|
| 11:31:06 | 20260924113106 |
| 11:41:06 | 20260924114106 |
| 11:44:06 | 20260924114406 |
| 12:03:35 | 20260924120306 |

休市时段（11:30-13:00）field[30] **随请求时间持续刷新**。
**结论：field[30] = 行情快照时间（≈服务器响应时间），不是最后成交时间。**
休市期间的真实最后成交时点，必须取分钟K线最后一根 bar 的时间戳（11:30）。

### 单位换算（内部统一口径）

- 成交量：原始「手」→ 内部「股」，×100
- 成交额：原始「万元」→ 内部「元」，×10000（如需精确值，用 field[35] 第三段）
- 原始值与单位同时保留，不丢弃

## 三、日线K线

响应结构：`data.{symbol}.qfqday`（请求 qfq 时）。同级还有 `qt`（实时快照）、`mx_price`、`prec`、`version`。

Bar 格式（6 字段）：
```
[date, open, close, high, low, volume]
["2026-09-24", "57.90", "56.83", "59.68", "56.50", "557262"]
```

- ⚠️ **字段顺序是 open,close,high,low（第2位是close不是high）**，已实证：当日bar第2位与实时价格精确一致
- volume 单位：**手**（与行情 field[6] 同口径）
- date 严格递增、无重复；周末/节假日缺口属正常
- 复权：qfq（前复权）。**当日（最新）bar 价格 = 未复权市价**（前复权以最新价为锚）；历史bar为调整后价格。跨周期价格比较必须统一用 qfq 口径
- 当日 bar 在收盘前为**未完成 bar**（close=当前价，随行情刷新）
- 实测 count=320 请求返回 321 根（含当日未完成 bar）

## 四、分钟K线（1分钟/5分钟）

响应结构：`data.{symbol}.m1` / `data.{symbol}.m5`

Bar 格式（8 字段）：
```
[timestamp, open, close, high, low, volume, {}, unknown]
["202609241130", "56.80", "56.83", "56.91", "56.80", "1602.00", {}, "1.40"]
```

- 同样为 open,close,high,low 顺序（第2位是close），已实证与实时价格一致
- timestamp 格式 `YYYYMMDDHHmm`
- volume 单位：**手**，且为**区间量**（非累计），已实证：当日全量求和 ≈ 行情累计量
- 字段[6]：空对象 `{}`，用途未知
- 字段[7]：**未知数值，不是固定单位的成交额**（实测其与 bar 真实成交额的比值在 6.5~6.7 间浮动，非恒定换算），**禁止参与任何计算**

### 时间戳语义（量额交叉验证锁定）

实证依据：
- m5 `1130` bar 成交量 7737 手 = m1 `1126+1127+1128+1129+1130` 五根求和 7737 手（**精确相等**）
- m5 `0935` bar 成交量 119899 手 = m1 `0930` (6310) + `0931~0935` (113589) = 119899 手（**精确相等**）

结论：

| 周期 | 时间戳含义 | 单日结构 |
|------|-----------|----------|
| m1 | **区间结束**；首根 `0930` 为开盘集合竞价特殊bar（09:30:00 成交），之后 `0931` 覆盖 (09:30,09:31]，`1130` 覆盖 (11:29,11:30] | 上午 121 根（0930~1130）+ 下午 120 根（1301~1500）= 241 根 |
| m5 | **区间结束**；首根 `0935` 覆盖集合竞价+(09:30,09:35] | 上午 24 根（0935~1130）+ 下午 24 根（1305~1500）= 48 根 |

- m1 下午首根为 `1301`（不是 1300），覆盖 (13:00,13:01]
- `1500` bar 含收盘集合竞价 (14:59,15:00]

### 未完成 bar 判定

- 交易中：最后一根 timestamp == 当前分钟所在区间结束 → **未完成**（量额仍在累积）
- 午休（11:30<t<13:00）：m1 末根 `1130` 已完成；m5 末根 `1130` 覆盖 (11:25,11:30] 也已完成
  （此前"5分钟11:30 bar不完整"的判断基于错误的区间开始假设，已修正）
- 日线当日 bar 收盘前始终视为未完成

## 五、质量检查规则（M1 实现依据）

1. 时间戳严格递增、无重复
2. 价格有效性：open/close/high/low > 0，且 high ≥ max(open,close)，low ≤ min(open,close)
3. volume ≥ 0；成交额（若使用）> 0
4. 跨接口校验：仅对**相同时间口径**的数据比对（当日分钟求和 vs 行情累计量）；禁止比较不同时间范围的累积量
5. 分钟缺口检测：按 241 根/日（m1）、48 根/日（m5）基准核对，剔除午休与休市时段
6. 日线与报价口径核验：qfq 当日 bar close 应等于实时价；不等则说明复权基准已变化，需重取并保留旧快照

## 六、已验证 / 不支持 / 未知清单

### 已验证（本轮实证）
1. 行情/日线/分钟线三端点可用，无需密钥
2. field[6]=手、field[37]=万元、field[35]第三段=元（精确）
3. field[30]=快照时间（非最后成交时间）
4. 分钟量=区间量；时间戳=区间结束；m1 首根0930为集合竞价特殊bar
5. 日线/分钟线字段顺序均为 open,close,high,low
6. 日线 qfq 当日价格=市价，历史已调整
7. 日线含当日未完成bar；分钟线无重复、严格递增
8. 分钟K线字段[7]非成交额，不可用

### 不支持（脚本层）
1. stock_query.py 不支持K线（已在技术分析Skill内新建适配器解决）
2. 接口均不支持自定义起止日期参数（已验证的参数位仅 count 与复权方式）

4. m15/m30/m60 是否可用（未实测）
